# Glossary

- **Claude iPhone**: the clean simulator this toolkit uses, created by `sim create`, always addressed by its UDID (the state's `udid`).
- **Profile**: which of the lab's two simulators a run uses. `clean` is the Claude iPhone: logged out, no extensions, erased by `sim reset`. `configured` is a second device, "Claude iPhone (configured)", saved by `sim create --profile configured` as `profiles.configured` (`{udid, name}`) in the state file; the owner's hand-made sign-ins and settings live on it, its Safari data is kept between sessions (`appium:noReset`), and only `sim reset --profile configured --yes` erases it. One is booted at a time (booting one shuts the other down, unless a session is live on it). Chosen by `lab up --profile` (default clean, never sticky). Which one a command acts on: `--profile`, else the recorded session's simulator, else the transient state `profile` (set by `lab up` and `sim boot`, cleared by `lab down` and `sim shutdown`), else clean. Agents never type credentials into either.
- **Unwarmed**: a simulator whose next boot is its first, when iOS migrates its data (about 11 minutes on a loaded 8 GB Mac). Listed in the state's `unwarmed` (`[UDID, ...]`): `sim create` sets it for a new device and `sim reset` for an erased one, a boot that finishes clears it, and a missing or damaged value means warmed. An unwarmed simulator may take 25 minutes to boot, a warmed one 10. `sim create` boots a new device once (the warm-up), so the first `lab up` is not the one that pays for it.
- **Run folder**: `runs/<YYYYMMDD-HHMMSS>-<label>/`, where screenshots, page source, `console.json`, `network.json`, `ui.json`/`ui.xml` and `run.log` for one test go. `sim run <label>` makes one and the next session started uses it; a session made after one that already had a session starts a new one. The newest 20 are kept.
- **Session**: one WebDriver session, from `safari start` to `safari stop`, always through Appium: on the simulator (private, logged out) or on the Phone (the owner's own Safari, in the lab tab only). One at a time.
- **Backend**: what drives a session: `appium`, for the simulator and the Phone alike (the Target says which). `safaridriver` is only a value an old state file may still hold: `safari stop` and `lab down` clean such a session up, nothing starts one. Recorded in the state file.
- **Trusted input**: touches and key presses made through the native layer (`safari tap`, `keys`, `swipe`), which the page sees as real (`isTrusted` true). `click` and `type` are synthetic and `isTrusted` is false.
- **Glass pane**: Safari's overlay during a safaridriver session that blocks other input. Appium sessions don't use it (but AXe input is still ignored during one). Only legacy sessions had it.
- **Phone layer / page layer**: `bin/sim` (simctl + AXe: what a finger does) vs `bin/safari` (WebDriver: what's in the page).
- **Inject**: running a userscript in the page through WebDriver after it loads, with a `GM_info` stand-in. Lost on navigation; `--reinject` runs it again, until `inject --forget <file>` (or `--clear`) drops it from the recorded list.
- **Lease**: the claim on the Claude iPhone, a file `lease.json` in the state dir (`{owner, since, expires}`, 15 minute TTL) taken or renewed by every command that drives the simulator or the session. Advisory: it only binds `sim`, `safari` and `lab`. Another owner is refused until it expires, is released, or is forced. Each take, renewal and release also records the time in `activity.json` (`{at}`), the idle stop's clock; so do `sim shot` and `sim ui`, which take no lease.
- **Owner**: who holds the lease: `MSL_OWNER`, else `CLAUDE_CODE_SESSION_ID`, else `user@host:tty` (`notty` without a terminal).
- **LaunchAgent**: Appium run by launchd as `com.dividedby.msl-appium` in the user's `gui/<uid>` domain, installed by `lab service install`. While it is installed `safari start` and `lab up` wait for it instead of starting Appium. `lab down` stops it and disables it (the plist stays) until the next `lab up`, so "installed but not loaded" is normal in between.
- **`lab up`**: the one command that checks the lease, Appium, the simulator and the session in order, repairs what is wrong, and reports what it found and did at each step.
- **`lab down`**: the opposite: ends the session, stops WebDriverAgent, shuts the Claude iPhone down, quits the Simulator or Device Hub window only if the lab opened it (recorded as `windowApp` in the state) and no simulator is booted, stops Appium (`--keep-service` leaves the service), and releases the lease. Best effort: a failed step is reported, the others still run, and the lease is kept.
- **Idle stop**: `lab down --idle`, run every 5 minutes by the LaunchAgent `com.dividedby.msl-idle` (installed with `lab service install`, `--no-idle-stop` opts out). The lab is idle when no lease is live and `activity.json` is older than 15 minutes (`MSL_IDLE_MINUTES`). It then takes a lease of its own (owner `msl-idle`, 10 minutes), does what `lab down` does, except that it shuts the simulator down only if the lab booted it (the state's `simBoot`), records the result as `idleStop` in the state, and hands the lease back.
- **Hold**: `lab hold [--minutes N]` (default 60, 1 to 120): `hold.json` (`{until}`) in the state dir, under which the idle stop does nothing until then, so a person can use the simulator by hand. Takes no lease; counts as activity. Ended by `lab down` and by a fresh simulator boot; a damaged file, or one ending more than 120 minutes ahead, is ignored.
- **Phone**: the owner's physical iPhone, saved once by `lab phone setup --udid <UDID> --team <TEAMID> [--bundle-id <id>]` as `{udid, teamId, bundleId, wdaExpires?, keyboard?, focus?, seen?}` in the state file (`seen` is `{osVersion, buildVersion, at}`, written only by `lab up` and `lab phone setup`). The UDID, team and bundle id come from there and nowhere else (never the code, never "the connected device"). `lab phone status` is read-only; `lab phone forget` removes the record. `setup` and `forget` are refused while a device session is open.
- **Target**: where a session runs: the Phone (`device`) or the Claude iPhone (`simulator`). `--target auto|device|simulator` on `lab up` and `safari start`; `auto` (the default) takes the Phone when one is saved, reachable and unlocked, the simulator when none is saved, and stops with a `needs` when a saved phone can't be reached. `--device <UDID>` is an alias that must equal the saved UDID. A reachable-looking phone is not enough: reachability comes from a live `devicectl` lock-state call and the usbmux listing, because the device list is stale when the phone has gone.
- **Transport**: how the Mac reaches the Phone: `cable` (wired, USB, through usbmux) or `wifi` (same network; through the Tunnel). Reported by `lab phone status` and `lab up` with `via` (`usbmux` or `tunnel`); a running device session records it as `transport` (`{via, address?}`) in the state. A USB entry in usbmux is the cable; otherwise a phone CoreDevice lists on the network that answers `lockState` is Wi-Fi. usbmux's own Wi-Fi ("Network") entries are ignored. Every page command works on both.
- **Tunnel**: Apple's native CoreDevice tunnel to the Phone over Wi-Fi, opened by `pymobiledevice3 remote start-tunnel --native` and held by one process, the tunnel host (`bin/lab-tunnel-host`), run by the LaunchAgent `com.dividedby.msl-tunnel` (installed by `lab service install`, no `RunAtLoad`/`KeepAlive`, started with `launchctl kickstart`, stopped with `launchctl kill TERM`). The host refuses any device but the saved Phone, serves a registry on `127.0.0.1` for Appium and records `tunnel.json` in the state dir (mode 0600): `{v, pid, udid, address, rsdPort, registryPort, startedAt, state: starting|up|down, reason?, detail? (the tool's exception line, for `rsd-failed`), strongboxWas, strongboxOurs}`. The `address` (`fd...`) is where WebDriverAgent listens on the Phone (port 8100). `lab up` starts it (step `tunnel`), `lab tunnel up|down|status` by hand, and `lab down`, the idle stop and choosing the cable stop it. A damaged `tunnel.json` counts as no tunnel (`lab tunnel down` removes it).
- **Needs**: the `needs` value in a failed device command, naming the one thing a person must do before it can work: `setup`, `xcode-account`, `keychain`, `developer-mode`, `trust`, `unlock`, `passcode`, `cable`, `tunnel-tool`, `tunnel`, `resign`, `slots`, `tab`, `service`, `unknown`. A failure carries `{ok:false, error, needs, human:[...], then, or}`: `human` the steps, `then` the command to run afterwards, `or` the way out (`lab up --target simulator`). An unattended run never prompts and never waits for a person.
- **Restore ledger** ([ADR 0007](docs/adr/0007-phone-settings-restore-ledger.md)): the record `state.phoneRestore` (`lib/phone-restore.js`) of Phone settings the lab changed and has not put back: `{udid, appearance?: {prior, set, at}, orientation?: {prior: {deviceOrientation, nonFlat}, set, at}, focus?: {prior: "unknown", set: "on", at}}`. The entry is written (with the value the Phone had) before the change is sent, keeps its `prior` if one is already there, and is cleared only after the Phone reads back the old value. The lab puts values back at `safari stop`, `lab down` (and the idle stop), and the next `lab up` after a crash, or on `lab phone restore`; it leaves a value the owner changed by hand (`ownerChanged`). Appearance restores to light or dark: whether it was on Automatic cannot be read (`restoredExactly: false`). `lab status` shows `phone.pendingRestore` (names only); `lab phone restore --forget` drops a damaged record. Applies to `safari appearance` and `safari orientation` (iPhone only, `devicectl`) and to Lab Focus (below); the keyboard settings keep their own mark (`keyboardPending`). Lab Focus cannot be read, so its entry has no readable prior and no read-back: the entry is cleared once the Off shortcut was delivered.
- **Lab Focus** (issue 16): the owner's own Focus called "Lab" on the Phone, turned on and off by two Shortcuts the owner made ("Lab Focus On", "Lab Focus Off"; other names with `lab phone setup --focus-on-shortcut/--focus-off-shortcut`, saved as `phone.focus`). `lab up` on the Phone runs the On shortcut (on by default; `--no-focus` or `lab phone setup --focus off` skip it) through `xcrun devicectl device process launch ... --payload-url shortcuts://run-shortcut?name=<encoded> com.apple.shortcuts`, in a `focus` step before the Lab tab is opened (the Shortcuts app is left in front). It is a kind in the Restore ledger; the restore runs the Off shortcut. The lab never runs a shortcut on a locked Phone (iOS would ask for the passcode and not run it) and cannot see which Focus is on, so a restore says `restoredExactly: false`. A shortcut that cannot be run is `focus: {applied: false, needs: "shortcut"}` in an `ok` `lab up`.
- **Slot lend** (issue 63, [ADR 0008](docs/adr/0008-slot-lending.md)): sideload lending the lab one of the Phone's free-account app slots (`sideload slot lend --udid <UDID> --to lab`) so WebDriverAgent fits, and taking it back (`slot return`). The lab's claim is the **lend record** (`state.slotLend`, phases `lending`, `lent`, `returning`), written before the lend and before WebDriverAgent is uninstalled; only sideload's answers settle it. The lab asks for a lend only in `lab up`'s `slot` step for a new Phone session, and only after installd refused the lab's own WebDriverAgent install with its free-app limit (`slot lend` never checks that the Phone is full). It gives the slot back at the idle stop, at `lab down` or a simulator `lab up` when nothing else would, or with `lab phone slot return`; never on a locked Phone or under an open session. A Phone `lab up` reuses a lend it holds.
- **Lab tab**: the Safari tab on the Phone that the lab opened for this session (the URL carries a one-run tag, held in `state.deviceTab`). The lab reads and drives this tab only; the owner's other tabs are never read, apart from one yes/no check at start that the attached page is the lab tab.
- **Pinned page**: the lab tab's WebKit page id, recorded when the session starts. Every device command checks the pinned page (and a token planted in it) is the current, visible page before and after it runs, and otherwise stops with `needs: "tab"` (unless the tab went to one of the session's *allowed hosts*, below). The session rests in the native context between commands, so a tab the owner switches to is never attached.
- **Page pin**: the lab's own Appium plugin, `msl-page-pin` (`appium-plugin/`), loaded with `--use-plugins`. It stops Appium following a page that appears, and refuses any script whose page is not the one the lab selected. A device session carries its `msl:pagePin` marker, or the lab ends it. Not the same as the *pinned page* above.
- **Taint**: the state of a run whose tab check failed or could not be read: the lab's own tab changed under it (navigated by hand or by the page to a site that is not an allowed host, closed, replaced). Switching to another of the owner's tabs is not a taint: it pauses the run, and native actions are refused (`needs: tab`) until the owner switches back. A tainted run discards the command's result, touches no other tab, and at `safari stop` / `lab down` closes nothing it can't verify (it says so, with `tabClosed: false` and a step for the owner).
- **Allowed host** (issue 101, [ADR 0009](docs/adr/0009-follow-allowed-hosts.md)): a host named with `safari start` / `lab up --allow-host <host>` (exact, http and https, up to 10), kept in the lab tab's record (`deviceTab.allowHosts`). When the lab's tab is found on one of them without its marker (the page, or the owner, navigated it there), the lab *follows* it: it marks the tab again, puts the collectors back, runs the command, and says `followed`. A taint drops the list; the next session names the hosts again. The simulator has no tab guard, so the list only applies on the Phone.
